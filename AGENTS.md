# Правила работы с репозиторием dawos

Плагин DeepSeek Harness: команды `/dawos-*` реализуют AWOS-пайплайн поверх
`context/` (спеки, продукт, источники).

## Перед коммитом

```sh
node test/verify.mjs     # ожидается VALIDATION: OK
```

## Чего не коммитить

- имена чужих проектов, локальные пути (`D:\...`, `C:\...`), номера задач из
  внешних трекеров, токены и ключи;
- результаты локальных прогонов — для них есть `.dawos/` и `/local/`, оба в
  `.gitignore`.

## Что где лежит

| Путь | Можно править |
|---|---|
| `lib/index.js` | да — команды, прокси, доставка промпта модели |
| `scripts/create-spec-directory.mjs` | да |
| `test/*.mjs` | да, с обезличенными данными |
| `prompts/*.md`, `templates/*.md` | нет — вендоренные файлы AWOS (MIT, см. `NOTICE`), обновляются целиком |
| `README.md`, `cordis.patch.yml` | да |

## Архитектурные опоры (не ломать без причины)

- `context/` проекта — источник истины; `.awos/` и `.claude/` — read-only прокси.
- Результат команды в DSH 0.2.x не рендерится в чате, поэтому информационные
  команды дублируют текст через `agent.followup` (`statusViaModel`).
- `@deepseek-ai/dsh-llm` может быть недоступен из профиля — `deliver()` обязан
  сохранять фолбэк на объект сообщения `{content, source}`.

## Локальный контекст

Если в рабочей папке есть `.dawos/HANDOFF.md` — прочитай его перед работой:
там история решений, состояние профиля и открытые задачи конкретной машины.
